HackFlow AI started as a deadline problem: judging projects manually was too slow, so I built an AI evaluation pipeline.

## The problem: hackathon judging does not scale

Manual judging breaks when dozens of teams submit repositories at once. Judges need signal fast: what was built, how much engineering exists, and whether the project works beyond the demo pitch.

## Designing the split: Node.js API + FastAPI ML pipeline

I separated product workflows from AI work. The Node.js REST API handled users, roles, submissions, and leaderboards, while the Python FastAPI service focused on repository analysis.

## Evaluating GitHub repositories with NLP

The pipeline read GitHub project data and generated evaluation signals using NLP. The goal was not to replace judges, but to reduce the boring manual scan before the actual decision.

## Building RBAC for organizers, judges, and participants

Organizers needed control, judges needed review access, and participants needed submission flows. JWT-based role checks kept those paths separate without overbuilding the first version.

## What broke, what shipped, and what I would rebuild

The hardest part was keeping two services aligned under hackathon pressure. If I rebuilt it, I would spend more time on background jobs, retries, and better scoring transparency.

If you are building hackathon tools or AI evaluation systems, study the workflow before touching the model.
