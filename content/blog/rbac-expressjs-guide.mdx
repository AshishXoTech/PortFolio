Role-Based Access Control (RBAC) is essential for any multi-user application. When building Rakshak Fraud Platform, we needed granular permissions for admins, analysts, and auditors — each with different access levels to fraud analysis data.

## Why Build It from Scratch?

Libraries exist for RBAC, but implementing it manually taught me how authorization actually works at the middleware level. Understanding the internals made debugging permission issues significantly easier and gave full control over the authorization flow.

## RBAC Fundamentals

RBAC assigns permissions to roles, and roles to users. Instead of checking individual permissions per user, you check the user's role:

- **Admin** — Full system access, user management, system configuration
- **Analyst** — View and flag transactions, run fraud reports, trigger AI analysis
- **Auditor** — Read-only access to audit logs and reports

## Implementation with Express.js

### 1. JWT Payload Design

Embed the user's role in the JWT payload:

```javascript
const token = jwt.sign(
  { userId: user._id, role: user.role },
  process.env.JWT_SECRET,
  { expiresIn: "24h" }
);
```

### 2. Authorization Middleware

Create reusable middleware that checks roles:

```javascript
const authorize = (...roles) => (req, res, next) => {
  if (!roles.includes(req.user.role)) {
    return res.status(403).json({ error: "Forbidden" });
  }
  next();
};
```

### 3. Route Protection

Apply middleware to protected routes:

```javascript
router.get("/transactions", authenticate, authorize("admin", "analyst"), getTransactions);
router.delete("/users/:id", authenticate, authorize("admin"), deleteUser);
```

## MongoDB Schema Design

Store roles as an enum on the User model with a separate Permissions collection for fine-grained control when needed. The three-tier model keeps the schema simple while supporting future permission expansion.

## Security Best Practices

- Always validate JWT on every protected route
- Use short token expiry with refresh tokens
- Log all authorization failures for audit trails
- Never expose role information in public API responses
- Implement rate limiting on authentication endpoints

## Outcome

This RBAC implementation secured Rakshak's fraud detection pipeline, ensuring analysts could flag suspicious transactions and trigger AI-powered fraud scoring without accessing admin-level system configuration. The pattern is now reusable across all our Node.js projects.
