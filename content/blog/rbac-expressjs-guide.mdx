I built RBAC by hand because I wanted to understand the permission model, not just install one.

## What RBAC actually means in a real Express API

RBAC is not a badge on a dashboard. It is every route deciding who can touch which action, and it gets messy when the product grows past one user type.

## Designing user, analyst, and admin roles

Rakshak needed a simple 3-tier model: users submit complaints, analysts review and score them, and admins manage the system. That model was small enough to reason about and strict enough to protect the workflow.

## JWT payloads, middleware, and route protection

I stored the role in the JWT payload, verified it in auth middleware, and added role checks at the route level. The important part was making the protected paths obvious in code.

## Avoiding common authorization mistakes

The easy mistake is checking authentication and forgetting authorization. Another one is hiding buttons in the UI but leaving the API route open.

## Testing permissions before trusting them

I tested routes by role, not just by happy path. Admin actions had to reject analyst tokens, and analyst actions had to reject normal user tokens.

Before adding an auth library, build the small version once so the abstractions make sense.
